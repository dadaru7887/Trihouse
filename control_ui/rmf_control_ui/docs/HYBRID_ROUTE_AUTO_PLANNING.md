# Hybrid Waypoint and Lane Automatic Route Planning Guide (Waypoint·Lane 혼합형 자동 경로 지정 가이드)

## 1. 목적

혼합형 자동 경로 지정은 맵 관리자가 배치한 벽, Home, 충전, 픽업 및 드랍오프를
기준으로 Open-RMF용 Waypoint와 Lane 초안을 자동 생성하는 기능입니다.

다음 두 분석기를 함께 사용합니다.

1. **Codex 온라인 분석**: 관제 서버가 OpenAI Responses API를 호출해 맵 구조와
   운영 시나리오를 분석합니다.
2. **로컬 오프라인 분석**: 인터넷이나 Codex 서버를 사용할 수 없을 때 앱에 포함된
   규칙 기반 생성기가 경로를 만듭니다.

Codex 연결 실패 때문에 맵 편집이 중단되지 않는 것이 혼합 방식의 핵심입니다.

## 2. 동작 순서

`맵 관리 > 시나리오 맵 자동 완성`을 실행하면 다음 순서로 처리됩니다.

1. 도면 크기와 벽 선분을 수집합니다.
2. 기존 Waypoint, Lane, 이름과 카테고리를 수집합니다.
3. 로봇 폭, 회전 반경, Localization 여유와 도면 축척을 수집합니다.
4. 로봇 수, Home·충전·픽업·드랍오프 수와 복귀 조건을 수집합니다.
5. Codex 분석 서버가 설정되어 있으면 온라인 분석을 먼저 요청합니다.
6. Codex 응답을 앱의 로컬 안전 규칙으로 다시 검증합니다.
7. 검증된 경우 적용 확인 창에 Waypoint와 Lane 수, 분석 요약 및 주의사항을
   표시합니다.
8. 사용자가 `Codex 제안 적용`을 누르면 편집 맵에 입력합니다.
9. 서버 미설정, 인터넷 단절, 시간 초과, 잘못된 응답 또는 안전 검증 실패 시
   오프라인 분석기로 자동 전환합니다.

Codex 제안을 취소한 경우에는 사용자의 선택을 존중하여 오프라인 결과를 추가로
생성하지 않습니다.

## 3. Codex에 전달되는 정보

Flutter 앱은 다음 맵 설계 정보만 게이트웨이에 JSON으로 보냅니다.

- 도면 파일 이름과 픽셀 크기
- 벽의 시작·끝 좌표
- 기존 Waypoint의 ID, 좌표, 이름과 카테고리
- 기존 Lane의 시작·끝 Waypoint와 방향
- 로봇 폭, 회전 반경, Localization 여유와 축척
- 운영할 로봇과 시설 수
- 작업 후 Home 복귀 및 운행당 적재 조건

현재 도면 이미지 바이트, MySQL 비밀번호와 OpenAI API 키는 이 요청에 포함하지
않습니다. API 키는 게이트웨이 프로세스에서만 읽습니다.

## 4. Codex 분석 서버 설정

개발용 게이트웨이는 Python 표준 라이브러리만 사용하므로 별도 패키지 설치가
필요하지 않습니다. 첫 번째 터미널에서 다음과 같이 실행합니다.

```bash
cd /home/gyi/robosapiens/rmf_control_ui
export OPENAI_API_KEY="발급받은_API_KEY"
python3 tools/codex_map_gateway.py
```

기본 주소는 다음과 같습니다.

```text
http://127.0.0.1:8787/v1/map/analyze
```

두 번째 터미널에서 Flutter 앱에 게이트웨이 주소를 전달합니다.

```bash
cd /home/gyi/robosapiens/rmf_control_ui
export ROBOSAPIENS_CODEX_MAP_ENDPOINT="http://127.0.0.1:8787/v1/map/analyze"
flutter run -d linux
```

두 환경변수는 각각의 프로세스를 시작하기 전에 설정해야 합니다. 이미 실행 중인
Flutter 앱은 나중에 변경된 환경변수를 읽지 않으므로 앱을 다시 시작해야 합니다.

### 4.1 모델 변경

게이트웨이의 기본 모델은 `gpt-5.6-terra`입니다. 모델을 변경하려면 게이트웨이를
실행하기 전에 다음 값을 설정합니다.

```bash
export ROBOSAPIENS_CODEX_MODEL="gpt-5.6-sol"
python3 tools/codex_map_gateway.py
```

### 4.2 포트 변경

```bash
export ROBOSAPIENS_CODEX_PORT="8790"
python3 tools/codex_map_gateway.py
```

이 경우 Flutter 앱의 endpoint도 같은 포트로 변경해야 합니다.

## 5. 완전 오프라인 사용

인터넷이 없는 관제 노트북에서는 Codex 관련 환경변수를 설정하지 않고 앱을
실행합니다.

```bash
unset ROBOSAPIENS_CODEX_MAP_ENDPOINT
flutter run -d linux
```

앱은 별도 오류 없이 로컬 생성기를 사용합니다. 로컬 생성기는 다음 작업을
수행합니다.

- 기존 Home·충전·픽업·드랍오프를 보존하고 목표 수량에 포함
- 모든 신규 Waypoint를 Floor 다각형 내부에만 배치
- Home 수만큼 `대기` 지점을 별도로 확보하고 충전소는 `충전` 지점으로 생성
- 부족한 역할만 이름 없는 대기 Waypoint에 배정
- 벽 끝 주변에 우회 Waypoint 생성
- 로봇 두 대의 안전 폭이 확보될 때만 가는 길과 오는 길을 서로 다른 두 줄의
  단방향 Lane으로 생성
- 좁은 통로는 양방향 공용 1경로로 만들고 양쪽 입구 가까이에 대기 지점 배치
- Home 신규 후보는 드랍오프에 가까운 위치를 우선 선택
- 기존 Waypoint 이름의 충전·Home·픽업·드랍오프·대기 키워드를 운영 역할로 인식
- 기존 주행망과 연결되지 않은 운영 지점 연결

## 6. 응답 안전 검증

Codex가 만든 결과는 즉시 실행 경로로 사용하지 않습니다. 앱은 적용 전에 다음을
검사합니다.

- 모든 Waypoint 좌표가 유한한 숫자인지
- Waypoint가 도면 픽셀 범위 안에 있는지
- 카테고리가 일반, 대기, 홈, 충전, 픽업 또는 드랍오프인지
- Lane의 시작·끝 ID가 실제 Waypoint를 가리키는지
- 시작점과 끝점이 동일하지 않은지
- Lane이 벽을 교차하지 않는지
- Lane이 벽 끝점에 닿거나 벽과 겹치지 않는지
- Lane 중심선이 로봇 반폭과 Localization 여유만큼 벽에서 떨어져 있는지
- Lane 방향이 양방향, 정방향 또는 역방향인지
- 신규 Waypoint와 Lane이 비어 있지 않은지

이 검사를 통과하지 못하면 Codex 결과 전체를 적용하지 않고 오프라인 분석으로
전환합니다. 적용 후에도 맵 관리의 `오류 검증`을 실행해야 하며, YAML 내보내기와
배포 단계의 기존 Open-RMF 검증은 그대로 유지됩니다.

오프라인 분석도 동일한 벽 안전 검사를 사용합니다. 우회 경로 중 한 구간이라도
안전거리를 만족하지 못하면 불완전한 Lane 일부를 남기지 않고 자동 생성 전체를
중단합니다.

## 7. 권장 작업 절차

1. 도면을 올리고 실제 길이를 측정해 축척을 설정합니다.
2. 벽을 자동 검출하고 잘못된 벽은 수정합니다.
3. 실제 위치가 정해진 픽업, 드랍오프, 충전 및 Home을 먼저 배치합니다.
4. `로봇 안전 기준`에서 폭, 회전 반경과 위치 추정 여유를 입력합니다.
5. `시나리오 맵 자동 완성`에서 로봇과 시설 수를 입력합니다.
6. Codex 또는 오프라인 제안의 경로를 화면에서 확인하고 적용합니다.
7. 좁은 통로의 Lane 방향, Mutex 그룹과 속도 제한을 수정합니다.
8. `오류 검증`을 실행하고 모든 오류를 해결합니다.
9. 실제 로봇으로 저속 시험한 뒤 맵을 배포합니다.

자동 결과는 편집 가능한 설계 초안입니다. 실제 설비 접근 방향, 문 열림 범위,
센서 사각지대, 사람 통행 구역과 정밀 도킹 공간은 현장 확인이 필요합니다.

## 8. 장애 처리

### `Codex 연결에 실패해 로컬 맵 분석으로 전환합니다`

- 게이트웨이가 실행 중인지 확인합니다.
- `ROBOSAPIENS_CODEX_MAP_ENDPOINT`의 주소와 포트를 확인합니다.
- 게이트웨이 터미널의 OpenAI API 오류를 확인합니다.
- 인터넷 연결을 확인합니다.

연결 대기 제한은 8초이고 전체 응답 대기 제한은 45초입니다. 실패한 요청 때문에
작업이 멈추지는 않으며 로컬 분석 결과를 계속 사용할 수 있습니다.

### `Codex 제안이 맵 안전 검증을 통과하지 못했습니다`

Codex가 도면 밖 좌표, 알 수 없는 연결 ID 또는 벽을 교차하는 Lane을 제안한
경우입니다. 벽 검출 결과와 도면 축척을 확인한 뒤 다시 실행하거나 로컬 초안을
수정합니다.

### API 키 관련 오류

`OPENAI_API_KEY`는 게이트웨이를 실행하는 터미널에 설정해야 합니다. Flutter 앱의
환경변수, 소스 코드, `.rmfproject` 또는 MySQL에 API 키를 저장하지 않습니다.

## 9. 운영 배포 시 주의사항

제공된 게이트웨이는 한 대의 관제 노트북에서 사용하는 개발·사내용 예제이며
`127.0.0.1`에만 바인딩됩니다. 여러 컴퓨터에서 공유할 때는 다음 항목을 갖춘 사내
서버 또는 리버스 프록시 뒤에 배치해야 합니다.

- TLS 적용
- 사용자 또는 장비 인증
- 요청 크기 제한과 호출 횟수 제한
- API 키를 Secret 저장소에서 주입
- 요청 실패 및 사용량 로그
- 외부 인터넷 장애 시 로컬 분석 전환 유지

관련 구현 파일은 다음과 같습니다.

- `lib/map_ai_service.dart`
- `lib/map_ai_service_io.dart`
- `lib/map_ai_service_models.dart`
- `lib/map_ai_service_stub.dart`
- `tools/codex_map_gateway.py`
