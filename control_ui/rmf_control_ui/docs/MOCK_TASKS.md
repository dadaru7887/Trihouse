# Pinky and OMX-AI Sequential Task Guide (Pinky · OMX-AI 연속 작업 가이드)

## 개요

`작업` 메뉴에서는 Pinky 주행과 OMX-AI 로봇팔 동작을 하나의 연속 작업으로
작성할 수 있습니다. 각 단계는 앞 단계가 정상 완료된 뒤에만 시작합니다.

```text
Pinky → 픽업3 이동
    ↓ 도착
OMX-AI → 화물 픽업 후 Pinky 데크에 적재
    ↓ 적재 완료
Pinky → 대기1 이동
```

## 사용 순서

1. 로봇 메뉴에서 배포 맵을 불러옵니다.
2. 시작 Waypoint를 선택해 Pinky 로봇을 Spawn합니다.
3. 작업 메뉴에서 `새 작업`을 누릅니다.
4. Pinky를 자동 또는 직접 배정합니다.
5. `단계 추가`로 실행 단계를 작성합니다.
6. 이동 단계의 지도 핀 버튼을 누르고 오른쪽 지도에서 목적지 Waypoint를 선택합니다.
   기존 목적지 드롭다운으로도 선택할 수 있습니다.
7. 카드를 드래그해 순서를 바꾸거나 휴지통 버튼으로 삭제합니다.
8. 나중에 실행하려면 `저장`, 즉시 실행하려면 `저장 후 시작`을 누릅니다.
9. 즉시 실행한 경우 목록에서 단계 진행률을 확인합니다.

## 작업 수정

작업 목록에서 작업 이름 옆의 연필 버튼을 누르면 기존 이름, 상세 지시, 배정 로봇과
실행 단계가 채워진 편집기가 열립니다. `저장`은 수정 내용만 MySQL에 반영하고
작업을 대기 상태로 둡니다. `저장 후 재시작`은 기존 진행 경로와 단계 상태를
초기화하고 수정된 작업을 1단계부터 다시 실행합니다. 완료·취소·실패한 작업도
같은 방식으로 수정하여 다시 실행할 수 있습니다.

다른 작업을 수행 중인 로봇으로는 변경할 수 없습니다. 자동 배정을 선택하면 현재
가용 로봇 중 배터리가 가장 높은 로봇을 사용합니다.

## 작업 목록에서 직접 실행

각 작업 이름 옆에는 `실행`, `수정`, `삭제` 버튼이 표시됩니다. 실행 버튼을 누르면
저장된 단계와 Waypoint를 1단계부터 시작합니다. 자동 배정 작업은 가용 로봇 중
배터리가 가장 높은 로봇을 사용하고, 특정 로봇 작업은 해당 로봇이 가용할 때만
실행합니다. 이미 실행 중인 작업은 중복 실행할 수 없습니다.

완료·실패·취소·대기 작업도 실행 버튼으로 다시 시작할 수 있습니다. 실행 시 이전
단계 상태와 실패 사유를 초기화하고 실행 사실과 이후 상태를 MySQL 이력에 기록합니다.

## 저장과 삭제

생성하거나 수정한 작업은 MySQL `robosapiens.rmf_ui_tasks`에 자동으로 저장되며
앱을 다시 실행해도 작업 목록에 복원됩니다. 앱 종료 당시 실행 중이던 작업은
안전을 위해 자동 실행하지 않고 `대기` 상태로 불러옵니다. 생성·수정·삭제와 상태
변경은 `rmf_ui_task_history`에 당시 전체 작업 데이터와 함께 누적 기록됩니다.

운영 맵을 변경해도 작업 목록은 삭제되지 않습니다. 실행 중인 작업은 대기 상태로
초기화되므로 새 맵의 Waypoint와 맞지 않는 작업은 수정 버튼으로 목적지를 다시
지정해야 합니다. 작업 이름 옆 휴지통 버튼을 누르고 확인하면 목록과 저장 파일에서
해당 작업을 삭제합니다. 삭제된 작업도 작업 이력 테이블에는 계속 남습니다.

## 주문 자동 분류와 연속 실행

작업 편집기의 `주문 자동 분류 규칙`에서 `모든 주문`, `상온 주문`, `냉장 주문`,
`냉동 주문` 중 하나를 선택하고 저장하면 해당 작업이 자동 실행 템플릿이 됩니다.
`수동 실행`은 주문과 연결하지 않는 일반 저장 작업입니다.

앱은 5초마다 MySQL `orders`에서 `expanded = 0`인 주문을 확인합니다. 주문 품목의
가용 재고 `lots.zone`을 기준으로 온도 구역을 분류하고 일치하는 템플릿을 찾아
주문별 실행 작업을 생성합니다. 가용 Pinky가 있으면 바로 1단계부터 실행하고,
없으면 대기 상태로 두었다가 로봇이 가용해질 때 자동 시작합니다.

작업 생성이 MySQL에 저장된 뒤 주문의 `expanded`를 1로 바꾸므로 같은 주문이
중복 실행되지 않습니다. 연결된 주문 번호는 작업 목록에 표시되며 분류·작업 생성
기록은 `events`와 `rmf_ui_task_history`에 함께 남습니다.

## 지원 단계

| 단계 | 실행 내용 |
| --- | --- |
| Pinky 이동 | 선택한 Waypoint까지 Lane 최단 경로로 이동 |
| 홈 복귀(자동) | 비어 있고 도달 가능한 가장 가까운 홈을 예약해 이동 |
| OMX-AI 픽업 | 현재 위치의 화물을 집어 Pinky 데크에 적재 |
| 대기 | 선택한 시간 동안 다음 단계를 시작하지 않음 |

편집기는 기본 예제로 `Pinky 이동 → OMX-AI 픽업 → Pinky 이동` 세 단계를
만듭니다. 첫 이동 목적지를 `픽업3`, 마지막 이동 목적지를 `대기1`로 바꾸면
요청한 작업이 완성됩니다.

작업 관리 화면 왼쪽에는 현재 운영 맵과 로봇 위치가 항상 표시됩니다. 작업
편집기의 지도에서는 선택 중인 이동 단계가 파란색 원으로, 다른 이동 단계가
보라색 원으로 표시되며 원 안의 숫자는 전체 작업 단계 번호입니다.

## 홈 풀 자동 할당

맵 관리에서 Waypoint 카테고리를 `홈`으로 지정하면 `홈1`, `홈2`처럼 자동으로
이름이 부여됩니다. `Home1`처럼 영문으로 시작하는 기존 Waypoint도 홈으로
인식합니다. 각 홈은 반드시 Lane 네트워크에 연결되어 있어야 합니다.

작업 편집기에서 `홈 복귀(자동)` 단계를 추가하면 다른 로봇이 점유하거나 예약하지
않은 홈 중 현재 위치에서 도달 가능한 가장 가까운 곳을 예약합니다. 여러 로봇이
동시에 복귀해도 같은 홈을 중복으로 예약하지 않습니다. 모든 홈이 사용 중이면
현재 위치에서 대기하고 자리가 비는 즉시 다시 계산합니다. 작업 취소·실패·삭제
또는 로봇 제거 시 예약은 자동 해제됩니다.

## 실행과 실패 처리

- 이동 단계는 현재 Lane 방향을 반영해 최단 경로를 다시 계산합니다.
- 목적지까지 갈 수 없으면 해당 단계와 전체 작업을 `실패` 처리합니다.
- OMX-AI 단계는 팔 동작이 끝나야 다음 단계를 시작합니다.
- 진행 중 작업을 취소하면 활성 단계와 나머지 단계가 취소되고 Pinky가 멈춥니다.
- 로봇을 제거하면 그 로봇의 진행 중 작업은 실패합니다.

## 실제 장비 연결 경계

현재 `rmf_control_ui` 화면의 실행은 앱 내부 로봇에서 확인하는 실행 모델입니다.
실제 장비 명령 형식은 기존 `robo_pinky_agent`와 동일하게 설계되어 있습니다.

- Pinky: 관제에서 `path`(Waypoint 배열) 전송
- OMX-AI: 관제에서 `load` 전송
- OMX-AI 완료: `loaded` 수신
- OMX-AI 실패: `loadFailed`와 사유 수신
- 취소: `abort` 전송

실제 Pinky와 OMX-AI를 움직이려면 로컬 Linux의 장비 게이트웨이(TCP 8788)와
Fleet Adapter가 실행 중이어야 합니다. 웹 브라우저가 로봇에 직접 명령하지 않고,
로컬 Edge Agent가 명령 전달과 안전 정지를 담당해야 합니다.

## 현재 제한사항

- 홈 예약의 현재 상태는 앱 실행 중 관리되며 배정 결과와 작업 상태는 MySQL 이력에 기록됩니다.
- 이 UI 자체에서는 아직 TCP 8788로 실제 명령을 보내지 않습니다.
- 여러 Pinky 사이의 Lane 예약과 충돌 회피는 RMF 연동 후 적용해야 합니다.
- 실제 OMX-AI 완료는 고정 시간이 아니라 `loaded` 응답으로 판정해야 합니다.

## 배차 순서

로봇이 모자라 대기가 쌓이면 **긴급도가 높은 작업이 먼저** 나갑니다. 긴급도는
주문에서 넘어오며 `긴급 > 높음 > 보통 > 낮음` 순입니다. 같은 긴급도끼리는 먼저
만들어진 작업이 먼저 나갑니다.

화면의 작업 목록은 새 작업이 위에 오도록 정렬되지만, 그 순서가 배차 순서는
아닙니다. 목록에 긴급도를 함께 표시하므로 왜 그 작업이 먼저 나갔는지 확인할 수
있습니다.

긴급 주문이 계속 들어오는 동안 보통 주문은 뒤로 밀립니다. 우선순위 배차의
성질이며, 같은 긴급도 안에서는 선입선출이 지켜집니다.

## 실시간 상태 보기

작업 이름 옆 `상세내용`을 누르면 담당 로봇의 상태가 실시간으로 표시됩니다.

- 현재 위치 (px과 미터)
- 주행 여부 · 배터리
- 목표 지점 · 남은 경로
- 단계별 진행 상태

`복사`로 지금 상태를 글로 가져갈 수 있습니다.

이 값은 앱 Mock 주행이 계산한 것입니다. 실제 로봇의 ROS 토픽 연결은
[Pinky 가상 로봇 · Fleet Adapter 연동](PINKY_FLEET_INTEGRATION.md)을 참고하세요.

## 로봇 원위치

작업 관리 상단의 `로봇 원위치`는 이동 로봇을 Spawn할 때 고른 Waypoint로
되돌립니다. Lane을 따라 실제로 이동하며, 갈 길이 없는 로봇은 그 자리에 바로
놓습니다.

진행 중이던 작업은 대기 상태로 돌아가 다시 배차됩니다. 되돌리기 전에 몇 건이
영향을 받는지 보여 주고 확인을 받습니다.
