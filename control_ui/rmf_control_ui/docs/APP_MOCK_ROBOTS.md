# App-Only Mock Robot Guide (앱 전용 Mock 로봇 가이드)

## 목적

`앱 Mock` 모드는 Gazebo와 RViz 창을 실행하지 않고 `rmf_control_ui`의 건물
도면 위에서 로봇 이동을 확인하기 위한 경량 시뮬레이션입니다.

이 모드는 Lane 연결, 방향, Waypoint 도달 가능성과 관제 화면을 빠르게 확인하는
용도입니다. 센서, 충돌 물리, 바퀴 미끄러짐 및 실제 로봇 제어는 시뮬레이션하지
않습니다.

## 사용 순서

1. `맵 관리`에서 이미지 도면을 불러옵니다.
2. Floor, Lane 및 Waypoint를 작성합니다.
3. 왼쪽 메뉴에서 `로봇`을 선택합니다.
4. 현재 편집 맵 대신 기존 배포 맵을 사용하려면 `배포 맵 불러오기`를 누릅니다.
5. 목록에서 `nav graph 확인됨` 상태인 맵을 선택합니다.
6. 로봇 실행 방식을 `앱 Mock`으로 둡니다.
7. `로봇 Spawn`을 누릅니다.
8. 로봇 유형, 고유한 이름과 시작 또는 설치 Waypoint를 선택합니다.
   필요하면 `캐릭터 이미지 선택`에서 PNG, JPG 또는 WebP 이미지를 지정합니다.
9. Spawn 후 로봇은 선택한 Waypoint에서 정지하며, 앱 지도와 오른쪽 목록에서
   상태를 확인할 수 있습니다.

## 기존 배포 맵 불러오기

`배포 맵 불러오기`는 프로젝트 루트의 `rmf_maps`를 검색해
`*.building.yaml`과 저장된 `*.rmfproject`를 목록으로 표시합니다. 정상 배포된
맵은 `nav graph 확인됨`으로 표시되고, 편집 상태가 보존된 파일은 `저장된 RMF
프로젝트`로 표시됩니다. 선택하면 PNG 도면, Lane, Waypoint 및 이름을 로봇 운영
화면에 적용합니다. 예전 `robosapiens.rmfproject`도 이 목록에서 다시 불러올 수
있습니다.

현재 운영 맵 이름은 로봇 화면 상단에 표시됩니다. 서로 다른 좌표계의 로봇이
섞이는 것을 막기 위해 운영 맵을 교체하면 기존 Mock 로봇은 모두 제거됩니다.

정상 배포된 맵의 권장 구조는 다음과 같습니다.

```text
rmf_maps/<맵 이름>/
├── <맵 이름>.building.yaml
├── <도면 이미지>.png
└── nav_graphs/
    └── 0.yaml
```

Spawn 자체는 위치 배치와 관제 등록만 수행하므로 로봇을 움직이지 않습니다.
`재개`를 누르거나 작업을 배정하면 Mock 로봇은 Lane의 `양방향`, `정방향`,
`역방향` 설정을 따라 이동합니다. 자율 이동 중에는 한 Waypoint에 도착하면 이동
가능한 다음 Lane을 선택하며 가능하면 직전 Lane으로 즉시 되돌아가지 않습니다.

## 로봇 제어

- `정지`: 현재 위치에서 이동을 멈춥니다.
- `재개`: 기존 위치에서 Lane 이동을 계속합니다.
- `삭제`: 앱에서 Mock 로봇을 제거합니다.

로봇 목록에는 이름, 이동 상태와 Mock 배터리 잔량이 표시됩니다.

## Spawn 가능한 로봇 유형

| 유형 | 동작 |
| --- | --- |
| Mock 주행로봇 | Lane을 따라 자율 이동하는 범용 테스트 로봇 |
| Pinky | 연속 작업에서 이동과 화물 운반을 담당하는 주행로봇 |
| OMX Manipulator | Lane이 없는 설비 Waypoint에 고정 설치되는 로봇팔 |
| Mock 휴머노이드 | Lane을 따라 보행하는 것으로 표현되는 경량 2D 휴머노이드 |
| Human | Lane을 따라 보행하는 것으로 표현되는 작업자 |

OMX Manipulator는 이동·일시정지 버튼을 표시하지 않습니다. Mock 휴머노이드와
Human은 도면 위에서 이동하지만 현재 Pinky 화물 운반 작업의 자동 배정 대상에는
포함되지 않습니다.

맵 관리에서 Waypoint 카테고리를 `설비`로 선택하면 현재 Lane 작성이 종료되고
연결되지 않은 고정 설치 좌표가 생성됩니다. OMX Spawn 목록은 이 설비 Waypoint를
우선 표시합니다. Pinky 등 이동 로봇의 Spawn 및 작업 목적지에는 Lane에 연결된
Waypoint만 표시됩니다. 기존 맵에 설비 유형 정보가 없으면 Lane 연결 여부를
기준으로 고정 설비 후보를 판별합니다.

각 Spawn 대상에는 개별 캐릭터 이미지를 지정할 수 있습니다. 선택한 이미지는 지도와
로봇 목록에서 원형 썸네일로 표시됩니다. 이미지를 선택하지 않으면 로봇 유형별 기본
아이콘을 사용하며, Human은 기본 사람 캐릭터로 표시됩니다.

## 실행 방식

| 방식 | 앱 Spawn | Gazebo/RViz | 용도 |
| --- | --- | --- | --- |
| 앱 Mock | 지원 | 필요 없음 | UI 및 Lane 이동 확인 |
| Headless Gazebo | 외부 백엔드 | 화면 없음 | 물리 시뮬레이션 |
| 실제 로봇 | Fleet 연동 | 필요 없음 | 운영 로봇 연결 |

현재 UI에서 직접 Spawn할 수 있는 방식은 `앱 Mock`입니다. Headless Gazebo와 실제
로봇은 외부 Fleet 백엔드가 위치와 상태를 제공해야 합니다.

## 제한사항

- Mock 로봇 상태는 메모리에만 있으며 앱을 종료하면 사라집니다.
- Mock 로봇은 rmf-web이나 실제 Fleet Adapter에 등록되지 않습니다.
- 여러 로봇 사이의 충돌 회피와 교통 협상은 수행하지 않습니다.
- 맵이나 Lane을 수정하면 기존 Mock 로봇을 삭제하고 다시 Spawn하는 것을
  권장합니다.
