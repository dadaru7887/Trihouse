# robo_control — RoboSapiens 물류 관제센터

상온·냉장·냉동 **3온도 물류센터**에서 자율주행 로봇 여러 대를 사람과 같은 공간에서
안전하게 운영하기 위한 **관제센터(FMS) 애플리케이션**입니다.
관제 로직을 실제로 구동·검증할 수 있는 결정론적 운영 시뮬레이터가 함께 들어 있습니다.

## 무엇을 하는가

| | |
|---|---|

| **스케줄링** | FEFO(유통기한) · 주문 긴급도 · 로봇 이동 동선 · 납기 · 대기 시간 가중 합산 |
| **안전** | 화재 / 전원 차단 / 작업자 위급 / 비상정지 / 바닥 결빙 상황별 자동 대응 시퀀스 |
| **인간-로봇 공존** | 보호 필드 1.7 m 정지 · 경고 필드 4 m 감속 · 로봇 간 교통 양보 |
| **환경 적응** | 온도·조도·바닥 마찰·경사를 주행 속도, 작업 시간, 측위 신뢰도에 실시간 반영 |
| **다중 로봇 조정** | 태스크 리스(단일 소유권 + TTL)와 자원 점유표로 중복 수행·충돌 차단 |
| **상태 공유** | 2초 주기로 상태·현재 태스크·진행률·점유 자원을 관제 및 타 로봇에 브로드캐스트 |
| **이력·기록** | 주행 궤적·작업 시간·오류·안전 이벤트 통합 이력, 주문/태스크별 성공·실패 확정 |
| **배터리** | 20% 절전(최소 동선) · 10% 충전소 복귀 · 안전 종료 후 재할당 · 예비기 단계적 투입 |
| **영속성** | SQLite 원장. 재고·주문·태스크·로봇·이력·안전 상황을 저장하고 재기동 시 복원 |
| **운영 조작** | 주문 직접 접수(FEFO 자동/로트 지정), 재고 조정·신규 로트 등록, 재고 원장 감사 추적 |
| **자원 관리** | 로봇·작업자 등록 및 해제. 해제 시 진행 태스크 안전 종료·재할당, 리스·자원·충전소 회수 |

## 빠른 시작

```bash
flutter pub get
flutter run -d linux      # 또는 -d macos, -d windows, -d chrome
```

권장 창 크기는 **1600 × 1000** 이상입니다(기본값). 더 작아도 동작하며,
폭 1100 미만에서는 사이드바가 아이콘만 표시되고 높이가 부족하면 세로 스크롤로 전환됩니다.

```bash
flutter analyze          # 정적 분석
flutter test             # 26개 테스트 (입고반영·주문접수·재고조정·리스·비상정지·FEFO·등록해제·4개 해상도 렌더링)
                         # DB 스키마·원장·영속성 테스트 5개는 ../robo_core 에 있습니다
```

## 데이터 저장소

원장은 **SQLite**이며 앱 상태는 캐시입니다. 기본 경로는
`~/.local/share/robo_control/robo_control.db` (환경 변수 `ROBOAPP_DB_DIR`로 변경 가능).

주요 테이블: `robots` · `robot_telemetry` · `workers` · `lots` · `stock_moves`(재고 원장) ·
`orders` · `tasks` · `task_steps` · `events` · `incidents` · `counters`.

앱은 [`DataStore`](../robo_core/lib/data/repositories.dart) 인터페이스에만 의존하므로,
PostgreSQL·REST 구현체를 만들어 갈아끼우면 UI와 제어 로직은 그대로 둘 수 있습니다.

## 실장비 연동

기동 시 로봇 링크 게이트웨이(TCP `8788`, 한 줄 = JSON 한 건)를 함께 엽니다.
여기에 접속한 로봇은 **위치·방위·배터리를 스스로 보고**하고, 관제는 경로
웨이포인트·안전 정지·속도 상한·충전만 하달합니다. 배차·FEFO·안전·재고 로직은
시뮬레이션 로봇과 완전히 동일하게 적용됩니다.

접속이 끊기면 해당 로봇의 태스크를 회수해 대기열로 되돌리고 배차 대상에서
제외하며, 재접속하면 자동 복귀합니다. 실장비가 붙어 있는 동안 배속은 1×로
고정됩니다.

구획마다 **적재 스테이션**(`LOAD-A`/`LOAD-C`/`LOAD-F`)이 있고, 여기에 접속한
로봇팔이 관제 지시를 받아 로봇에 화물을 실어 줍니다. 출고 태스크는 랙 집품 →
적재 스테이션 → 출고 도크 순으로 진행됩니다.

참고 구현: [`robo_pinky`](../robo_pinky/) — ROS 2 Jazzy + Gazebo Harmonic 위의
Pinky 3대 + OpenMANIPULATOR-X 3대. 프로토콜 명세와 좌표계는
[설계 문서](../robo_pinky/docs/PROJECT_SUMMARY.md), 실행 방법은
[사용 설명서](../robo_pinky/docs/USER_GUIDE.md)에 있습니다.

## 현재 범위

관제 로직과 운영 정책의 **실행 가능한 명세**입니다. 로봇 거동은 시뮬레이션
또는 Gazebo 물리 시뮬레이션이며, 표준 프로토콜 정렬(VDA 5050), 로봇 측 지역
경로 재계획, 안전 인증 부품 적용 등 현장 배포에 필요한 작업은
[PROJECT_SUMMARY.md §10](docs/PROJECT_SUMMARY.md#10-한계와-향후-과제)에 정리되어 있습니다.
