# Pinky SR

## 분석 범위

- `System Requirements.md`의 활성 요구사항 중 Subject에 Pinky가 포함된 Priority `High`, `Medium` 요구사항 9개를 대상으로 한다.
- `pinky_pro` 내장 코드에서 재사용할 수 있는 패키지, ROS 2 토픽·서비스·액션과 추가 구현이 필요한 부분을 구분한다.
- Pinky는 물품을 목적지까지 운반하고 정차하며 자동 하차는 수행하지 않는다.
- 대기·충전소 복귀는 지정 위치까지의 이동만 포함하며 충전 단자 접촉은 자동화하지 않는다.
- 로드셀과 무게 기반 판단은 사용하지 않는다.

## LED·LCD·부저 표시 규칙

| Pinky 상태 | LED | LCD | 부저 |
| --- | --- | --- | --- |
| 정상 이동 | 표시하지 않음 | 현재 목적지 구역 표시 | 끔 |
| 사람 또는 장애물 감지 | 주황 | 현재 목적지 구역 유지 | 끔 |
| 사람 쓰러짐 비상상황 | 빨강 | 현재 목적지 구역 유지 | 켬 |
| 목적지 도착 또는 작업 취소 | 표시하지 않음 | 목적지 문구 해제 | 끔 |

- LED 표시 우선순위는 `사람 쓰러짐 비상상황 > 사람·장애물 감지 > 표시 없음`으로 한다.
- 사람 또는 장애물이 안전 범위에서 벗어나면 주황 LED를 끈다.
- 빨간 LED와 부저는 비상 해제 명령을 받은 경우에만 끈다.
- LCD 목적지는 FMS가 전달한 목적지 코드에 따라 `냉동창고`, `냉장창고`, `상온창고`, `포장대`, `대기/충전소 복귀` 중 하나만 표시한다.
- 목적지 코드가 위 목록에 없으면 임의 문구를 표시하지 않고 LCD를 비운다.
- 기존 `pinky_lcd.py`의 이미지 출력 기능을 재사용하고, PIL로 목적지 텍스트 이미지를 생성하는 ROS 2 서비스를 추가한다.
- 한글이 깨지지 않도록 프로젝트에 한글 폰트 파일을 포함하며, `대기/충전소 복귀`처럼 긴 문구는 두 줄로 가운데 정렬한다.

## 작업 수행 완료 예상 시간 산정

작업 할당 시점에는 FMS 주행 그래프를 사용해 사전 예상 시간을 계산하고, Nav2가 실제 경로를 생성한 뒤에는 해당 구간의 예상값을 Nav2 경로 기반 예상값으로 교체한다. 두 경로의 길이를 더하지 않는다.

```text
구간 예상 시간 = Nav2 경로 길이 / 실험으로 측정한 구간별 유효 속도

작업 완료 예상 시각 =
현재 시각
+ 남은 구간의 예상 주행 시간
+ OMX 파지·적재 예상 시간
+ 작업 위치 정차·준비 시간
```

- 작업 배정 전에는 FMS 주행 그래프의 구간 길이와 Pinky의 예상 작업 종료·복귀 시각을 사용한다.
- Nav2 목표 전송 후에는 `/plan`의 Pose 간 거리를 합산한 경로 길이로 해당 주행 구간의 예상 시간을 갱신한다.
- Nav2가 경로를 다시 생성하면 남은 경로 길이로 도착 예상 시각을 다시 계산한다.
- Nav2의 설정 속도 0.2 m/s를 그대로 사용하지 않고 실제 가속, 감속, 회전과 정차 시간이 포함된 유효 속도를 사용한다.
- 일반 통로, 회전·좁은 통로, OMX·포장대 최종 접근의 세 구간 유형을 각각 3~5회 주행하고 중앙값을 사용한다.
- 초기 예상값에는 측정 오차를 고려해 10~20%의 여유 시간을 둔다.
- Nav2가 경로를 생성하지 못하면 완료 예상 시각을 확정하지 않고 작업 시작을 보류한다.

OMX 사전 파지 명령 시각은 다음과 같이 계산한다.

```text
OMX 파지 명령 시각 = Pinky 예상 도착 시각 - OMX 평균 파지 시간 - 준비 여유 시간
```

- 계산된 명령 시각이 현재보다 이전이면 OMX에 즉시 파지 명령을 전송한다.
- OMX가 Pinky보다 먼저 파지를 마치면 등록된 안전 대기 자세에서 Pinky 도착을 기다린다.
- Pinky 도착 예상 시각이 1~2초 이내로 변한 경우에는 OMX 명령 일정을 다시 계산하지 않는다.

## 권장 추가 노드

### `pinky_fleet_agent`

- FMS/RMF 목적지를 Nav2 `NavigateToPose`로 전달한다.
- Nav2 결과, 위치, 배터리, 작업 단계와 완료 예상 시각을 FMS에 전달한다.
- 대기·충전소 복귀, 포장대 변경과 도착·정차 상태를 처리한다.
- FMS가 전달한 목적지 코드를 LCD 표시용 구역 문구로 변환하고, 목적지 도착 또는 작업 취소 시 문구를 해제한다.
- 기존 `nav2_web_server.py`의 액션·TF·경로 구독 코드는 재사용하되 Flask 서버는 중복 실행하지 않는다.

### `pinky_safety_controller`

- Nav2 속도, 초음파·LiDAR, YOLO 사람 감지와 비상 상태를 입력받는다.
- 안전 조건을 적용한 최종 속도만 모터의 `/cmd_vel`로 전달한다.
- 사람 또는 전방 장애물이 보호 영역에 들어오면 Nav2 목표를 유지한 채 속도를 0으로 제한한다.
- 비상 해제 전까지 새 목표와 속도 명령을 차단한다.
- 사람 또는 장애물 감지 중에는 주황 LED를 켜고, 사람 쓰러짐 비상상황에는 빨간 LED와 부저를 켠다.

## 실행 구성 주의사항

- 기본 `pinky_bringup/launch/bringup_robot.launch.xml`은 LiDAR, 모터·오도메트리와 배터리 노드만 실행한다.
- 초음파, IMU, LED, `pinky_fleet_agent`와 `pinky_safety_controller`를 함께 실행하는 Trihouse 전용 launch 파일이 필요하다.
- `pinky_pro`에는 실제 카메라 RTSP 송신과 YOLO 사람 인식 노드가 없다. URDF의 카메라 정의는 프레임과 시뮬레이션 모델이므로 실제 영상 송신은 별도 비전 구현을 사용한다.
- 현재 분석은 소스 정적 확인 기준이다. Pinky ARM64, ROS 2 Jazzy 환경에서 센서 토픽, LED, Nav2 정차 오차와 유효 속도를 실제 검증해야 한다.
