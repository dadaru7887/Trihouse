> 지금 무엇을 하는 중인지, 이 폴더의 문서를 어떤 순서로 읽는지, 바깥의 어떤 정본을
> 참조하는지, 손대기 전에 알아야 할 함정이 거기 있다.


Claude 가 세운 설계와 계획 문서가 여기 모인다.

기존 `docs/superpowers/{specs,plans}/` 와 나누는 기준은 **누가 그것을 다시 읽는가**다.
`docs/superpowers/` 는 지금까지 쌓인 것이고, 이 폴더는 앞으로 Claude 에게 시킬 일의
설계와 계획을 둔다. 사람이 검토하고 승인하는 대상이므로 한곳에 모아 둔다.

## 살아 있는 문서 하나

[p0-stack-reference.md](p0-stack-reference.md) 는 날짜가 없다. 스택 2층 구조와 질답을
계속 덧붙여 쌓는 문서라서 스냅샷 규칙에서 뺐다. 새 질문에 답할 때마다 7절에 덧붙인다.

## 파일 이름

`YYYY-MM-DD-<주제>-{design,plan}.md`

`design` 은 무엇을 왜 하는지 합의한 것이고, `plan` 은 그것을 Task 와 체크박스로
편 것이다. 설계 없이 계획만 있는 문서는 두지 않는다.

## 규칙

- 계획을 실행하면서 **체크박스를 그 자리에서 갱신한다.** 다 끝난 뒤 한꺼번에
  칠하지 않는다.
- 실측 결과는 계획 문서가 아니라 `docs/validation/` 에 적는다. 계획은 "무엇을 할
  것인가", validation 은 "무엇이 나왔는가"다.
- 계획이 틀린 것으로 드러나면 지우지 말고 **왜 틀렸는지 적고 새 문서를 만든다.**
