Trihouse · Memory Architecture

검증된 길과 과거 경험을
현재의 판단으로 바꾸는 방법

Reference Memory와 Episodic Memory는 과거를 그대로 따라 하기 위한 저장소가 아니다. 현재 센서와 실행 결과를 이용해 기억의 신뢰도를 계속 갱신하는 판단 재료다.

아주 쉽게 말하면: Reference Memory는 관리자가 확인한 도로 지도이고, Episodic Memory는 로봇이 실제로 겪은 운행 일지다. 지도에서 갈 수 있는 곳을 찾고, 운행 일지에서 성공과 실패를 배운 뒤, 현재 센서로 다시 확인하고 움직인다.
Reference Memory

검증된 좌표와 연결

  • Node: 안전하게 정지·대기·복귀할 수 있는 좌표
  • Edge: Node 사이의 허용된 연결과 방향
  • map version, 마지막 검증 시각, 사용 상태를 함께 저장
  • VLM이나 RL이 자동으로 수정하지 않음
Episodic Memory

실행과 결과의 기록

  • 어떤 상황에서 어떤 좌표·skill을 선택했는지 저장
  • Safe: 안전하게 복구하고 기존 task를 재개한 경험
  • Critical: 실패·근접사고·안전장치 개입 경험
  • 새 결과가 쌓일 때마다 신뢰도를 갱신

기억을 현재에 맞추는 법

과거 경험이 지금도 맞는지는 다음 네 가지를 곱해 판단한다.

적용 가능성 = 상황 유사도 × 버전 호환성 × 최신성 × 결과 신뢰도

상황이 닮았더라도 map이나 robot version이 다르면 낮게 평가한다. 오래된 Safe 경험은 점차 약하게 보고, 충돌과 같은 Critical 경험은 더 오래 보존하되 현재 geometry와 맞는지 다시 확인한다.

가장 중요한 규칙: 과거에 100번 안전했더라도 현재 LiDAR나 costmap이 위험하다고 하면 실행하지 않는다. Memory는 후보를 추천할 뿐, 현재의 안전을 보증하지 않는다.

1. 후보를 찾는다

Reference Memory에서 가까운 안전 Node와 원래 경로로 합류할 Node를 찾는다. Episodic Memory에서는 현재와 비슷한 Safe·Critical 경험을 각각 찾는다.

2. 위험 후보를 먼저 버린다

현재 map version, localization, LiDAR, costmap, keep-out zone, robot footprint를 통과하지 못한 후보는 RL이 점수를 매기기 전에 제거한다. Critical 경험과 매우 유사한 충돌·사람 침범 행동도 veto한다.

3. 안전 후보 안에서만 고른다

최종 후보 = 안전 조건을 통과한 후보 중 task 재개 가능성이 가장 높은 좌표

안전성과 효율을 한 점수로 섞지 않는다. 먼저 안전하지 않은 후보를 없애고, 남은 후보 안에서 RL이 성공 가능성을 비교한다.

4. 바로 달리지 않고 계획부터 검사한다

선택한 좌표는 먼저 Nav2의 경로 계산만 수행한다. 전체 path의 충돌과 clearance를 확인한 뒤 짧은 waypoint만 실행하고 다시 정지·관측한다. 실행 중에는 Safety Supervisor가 속도를 계속 감시한다.

Example

상황: 전방의 정체불명 상자가 통로를 막음

Reference: 뒤쪽 0.5m에 검증된 복귀 Node가 있음

Safe 기억: 같은 구역에서 짧은 후진 후 재계획 성공 6회

Critical 기억: 왼쪽 우회 중 사람 안전영역 침범 1회

결정: 왼쪽 후보는 제거하고 후방 Node까지의 path를 사전검증한 뒤 저속으로 짧게 실행

5. 결과로 Memory를 갱신한다

성공했다면

새 Safe episode를 추가하고 유사 행동의 신뢰도를 높인다. 반복 성공한 provisional 경험은 verified로 승격한다.

실패하거나 위험했다면

Critical episode를 추가한다. 관련 Reference Node는 즉시 삭제하지 않고 suspect 또는 quarantine으로 전환해 재검증한다.

순환의 의미: 오늘의 실행 결과가 내일의 검색 순위와 위험 판단을 바꾼다. 그래서 Memory는 과거 기록이지만 판단은 점차 현재 환경에 맞춰진다.

왜 별도로 두는가?

모든 운행 기록을 같은 비율로 학습하면 흔한 정상 사례가 대부분을 차지해 드문 위험 상황을 잘 배우지 못한다. 반대로 Critical만 과도하게 학습하면 로봇이 지나치게 멈추는 정책이 될 수 있다. Sampler가 두 종류의 균형을 조절한다.

Sampler가 뽑는 transition

(현재 상태, 선택한 후보, 받은 결과, 다음 상태, 종료 여부)

예를 들면 “전방 상자·후방 free space 상태에서 BACKOUT_RIGHT 후보를 선택했고, 안전하게 route로 복귀했다”가 하나의 학습 사례가 된다.

각 episode의 뽑힐 가능성

wᵢ = 희소성 × 최신성 × 데이터 신뢰도 × 학습 가치
P(i) = wᵢ ÷ 모든 w의 합
  • 희소성: 사람 침범·근접사고처럼 드문 사례에 더 큰 기회
  • 최신성: 현재 map과 robot에 가까운 경험을 우선
  • 데이터 신뢰도: 검증된 센서와 operator label이 있는 경험을 우선
  • 학습 가치: RL 예측이 실제 결과와 크게 달랐던 사례를 우선

수식은 어렵게 보이지만 뜻은 간단하다. 자주 보지 못했고, 최근이며, 믿을 수 있고, 현재 모델이 틀렸던 경험일수록 다시 공부할 확률을 높인다.

Safe·Critical 결과와 provenance를 잃지 않는다. 오래된 데이터도 분석과 재현을 위해 archive에 남긴다.

Replay View

현재 학습에 맞게 선택

map version이 다르거나 quarantined인 episode는 제외한다. sampling 정책은 바꿔도 원본은 변하지 않는다.

Reference Memory는 replay transition으로 섞지 않는다. Reference는 “가능한 좌표와 연결”을 제공하고, Episodic Memory는 “그 좌표를 선택했을 때 실제로 무슨 일이 일어났는가”를 제공한다. RL은 후자의 결과로 학습한다.

연구 배경: ReMemNav의 bounded episodic working memory, Retrieval-Augmented RL과 RANa의 경험 검색, EE-RL의 rare-critical replay 관점을 Trihouse의 Nav2·Safety 경계에 맞게 재구성했다. 참고: ReMemNav · Retrieval-Augmented RL · RANa · EE-RL
