1. 핵심 결론

권한 한 문장
VLM + RL은 좌표를 추천하고, Nav2는 경로를 결정하며, Safety Supervisor는 실제 움직임을 허가한다.
VLM화면에서 문제 객체의 위치·위험과 로봇이 시도할 후보 방향을 읽는다.
Reference Memory관리자와 반복 실행으로 검증한 장소 Node와 이동 Edge다.
Episodic Memory로봇이 실제로 실행한 복구와 결과를 남긴 운행 일지다.
TGRPO → SAC어떻게 벗어날지 Top-K skill을 고른 뒤, 각 skill 안에서 좌표를 만든다.
6C-Lite실제로 움직이지 않고 모든 후보의 가까운 미래를 짧게 시험한다.
Nav2 + Safety실제 경로를 재계획하고, 센서와 정지거리로 최종 속도를 허가·차단한다.
하지 않는 것
VLM/RL은 /cmd_vel을 직접 내지 않는다. 복구 모듈은 별도 Nav2 action client가 되지 않는다. 사람 안전을 학습 점수와 맞바꾸지 않는다.

3. Composite Trigger와 완전 정지

TVLM = Thard ∨ Tambiguity ∨ Tdisagreement ∨ Tnavigation
뜻: LiDAR/bumper 같은 즉시 위험, YOLO의 지속적 모호성, 영상·segmentation·depth의 불일치, Nav2 stuck 중 하나라도 발생하면 복구를 시작한다. Hard 조건은 즉시, 모호성은 N-of-M 프레임과 hysteresis로 판단한다.

학습하지 않은 객체는 이름을 맞히기 전에 장애물로 처리한다. 낮은 confidence, class 불안정, 설명되지 않는 depth/segmentation 영역을 unknown occupied region으로 표시한다. VLM은 그 뒤에 의미와 위험을 보조한다.

정지했다고 인정하는 네 조건

  1. Safety Supervisor STOP latch 활성
  2. odometry 속도가 threshold 아래에서 일정 시간 유지
  3. Fleet Adapter가 기존 Nav2 goal cancel ACK
  4. 정지 뒤 timestamp의 동기화 snapshot 확보
Recovery epoch
Trigger마다 세대 번호를 올린다. 센서, VLM 출력, 후보, Nav2 goal의 epoch가 다르면 늦게 도착한 옛 답으로 보고 폐기한다. 동시에 유효한 goal은 정확히 하나다.

4. VLM 입력·출력 계약

입력RGB 프레임(단일/연속은 D25), 같은 시점 segmentation, YOLO bbox·confidence·track, pose·LiDAR/depth·임무 방향
운용위험·예외 시에만 3B 또는 7B 4-bit 모델 load/infer, LoRA 적용. YOLO는 저주기로 계속 추적한다.
{
  "observations": [{
    "bbox_norm": [0.62, 0.08, 0.91, 0.74],
    "semantic_label": "person_or_unknown_dynamic",
    "risk": "critical", "confidence": 0.78
  }],
  "robot_candidate_sectors": [
    {"angle_deg": -90, "width_deg": 25, "preference": 0.73}
  ],
  "uncertainty": 0.28
}

VLM은 자유문장이나 metric 좌표를 직접 내지 않는다. 화면의 정규화 bbox와 로봇이 시도할 방향을 strict JSON으로 낸다. calibration, TF, LiDAR/depth association과 SAC가 이를 map 좌표로 바꾼다. critical 객체의 3D association이 불확실하면 해당 시야를 빈 공간으로 보지 않는다.

5. Reference Memory + Episodic Memory 스키마

MapRevision
 ├─ ReferenceNode ── ReferenceEdge ── ReferenceNode
 │        └─ RecoveryEpisode ── EpisodeStep ── CandidateRollout
 │                                  ├─ IncidentFact (불변)
 │                                  └─ OutcomeAssessment (갱신 가능)
 └─ localization epoch / TF snapshot

PolicyBundle = TGRPO checkpoint + SAC checkpoint + skill ontology + schema

ReferenceNode — 검증된 장소 점

필드군내용왜 필요한가
ID·공간node_id, map_id, map_revision, x,y,yaw, frame_id좌표가 어느 지도에서 검증됐는지 고정한다.
용도node_type, recovery_roles[], allowed_heading_range대기점·후퇴점·재합류점의 허용 행동을 구분한다.
안전footprint_class, static_clearance_m로봇 몸 전체가 들어가고 여유가 있는지 기록한다.
현재성last_verified_at, status, alpha, beta, source_hash오래되거나 의심되는 점을 ACTIVE/SUSPECT/QUARANTINED로 관리한다.

ReferenceEdge — Node 사이의 검증된 이동 연결

필드군내용왜 필요한가
연결edge_id, from_node_id, to_node_id, directionality어느 점에서 어느 점으로 갈 수 있는지 나타낸다.
경로path_polyline, min_width_m, min_clearance_m, speed_limit중심점뿐 아니라 이동 공간을 보존한다.
문맥allowed_recovery_skills[], dynamic_risk_profile후진 허용과 사람 출현 같은 제약을 기록한다.
현재성map_revision, status, last_verified_at, alpha, beta지도와 실제 결과가 바뀌면 격리한다.

Episodic Memory — 하나의 schema, 결과는 연속값

Entity핵심 필드파인만식 설명
RecoveryEpisodeepisode/epoch, trigger, map/localization version, 시작 pose, model bundle, terminal status, budget위험을 발견해 멈춘 때부터 임무에 돌아가거나 포기할 때까지의 전체 이야기다.
EpisodeStepsnapshot, retrieved IDs, high action, selected pose, actual Nav2 path, execution, reward, next state실제로 선택하고 실행한 짧은 좌표 한 번이다. 최종 후보만 들어간다.
IncidentFactcollision/emergency/human intrusion, severity, sensor evidence, immutable hash충돌 같은 사실은 나중에 모델이 안전했다고 덮어쓰지 못한다.
OutcomeAssessmentp_safe, p_boundary, p_critical, margin, progress, intervention, label confidence성공과 실패 사이의 “간신히 성공”을 경계 확률로 보존한다.
CandidateRollout출처, skill/좌표, filter 결과, trajectory 요약, risk upper bound, uncertainty, selected, TTL실행하지 않은 후보의 가상 시험표다. 실제 성공 경험으로 위장하지 않는다.
Critical과 Reference
관련 Reference Node는 즉시 삭제하지 않는다. 일시적인 사람 때문인지 좌표 자체가 틀렸는지 모르므로 먼저 SUSPECT/QUARANTINED로 바꾸고 재검증한다.
Rref = α/(α+β) · e−λΔt · Cmap · Cloc
뜻: α는 안전 확인, β는 위험 확인, Δt는 마지막 검증 뒤 시간, Cmap은 지도 일치, Cloc은 위치추정 품질이다. 여러 번 안전했어도 오래됐거나 지도가 바뀌면 다시 의심한다.

MySQL이 원본이고 RTX 5080 PC에는 FAISS index, 최근 cache, 네트워크 단절용 append-only queue를 둔다. event마다 UUID·epoch·step·schema/model version·checksum을 넣고, 로봇은 DB가 아니라 API로 접근한다.

6. 후보 생성과 계층형 RL

후보는 Reference Node/Edge, 유사한 safe/boundary Episode, Critical 반대 제약, TGRPO+SAC에서 모은다.

zt(k) ~ πH(z | st),   k=1,…,K
s_t는 영상·segmentation·LiDAR·pose·Memory 검색 결과, π_H는 TGRPO 상위 정책, z는 후진·좌우 우회·대기 후 재관찰 같은 고수준 action, K는 Top-K 수다.
pt(k,m) ~ πL(p | st, zt(k)),   p=(x,y,yaw),   m=1,…,M
π_L은 SAC 하위 정책이고, 각 상위 action을 조건으로 M개 map 좌표를 만든다. GPU batch로 함께 계산해도 의미는 상위 방법 → 그 방법에 맞는 좌표 순서다.
1안(기존 방안 B) · 채택

직접 bounded absolute map pose

SAC가 (x,y,yaw)를 직접 내되 Recovery Envelope 안으로 제한한다. map revision, localization epoch, TF snapshot, covariance, timestamp를 후보에 묶는다.

장점: Nav2 연결과 결과 해석이 직접적. 단점: map 변경·OOD에 민감.

2안(기존 방안 A) · 대안

Reference anchor + bounded residual

p = panchor + Δp, ‖Δp‖ ≤ rmax

장점: 검증점 주변이라 데이터 효율·안전 설명이 좋음. 단점: Reference가 드문 미지 공간에서 덜 유연.

7. 후보 0~6단계 필터

규칙: 위험을 점수로 상쇄하지 않는다. 사람 침범 후보는 진행 점수가 아무리 높아도 즉시 탈락한다. 0~3은 생성 시, 4~5는 모든 후보 rollout, 6은 우승 좌표 하나의 최신 재검사다.

8. 6C-Lite: 모든 후보의 가상 n-step

0~3은 현재 시점의 입장권 검사이고, 4~5 rollout은 미래 path 전체의 시간 변화 검사다. 따라서 같은 규칙의 불필요한 중복이 아니다. 영상 생성은 하지 않고 Nav2 geometry rollout, 구조화된 동적 객체 predictor, 작은 world-model ensemble만 사용한다.

τi = (ŝi,0, ŝi,1, …, ŝi,n)
τ_i는 후보 i의 가상 미래, ŝ_i,j는 j step의 pose·사람·장애물·clearance·불확실성, n은 미리 볼 가까운 step 수다. 실제로는 아직 움직이지 않는다.
RiskiUCB = meane(Riski(e)) + κ · stde(Riski(e))
평균 위험에 모델 간 의견 차이를 더한다. 여러 가상모델이 서로 다르게 말하면 그 자체를 위험으로 본다.

Tournament 순서

  1. 모든 hard rule 통과
  2. 사람·critical·unknown 위험 상한 최소
  3. 불확실성 최소
  4. Nav2 clearance·정지 가능성 최대
  5. 그 뒤에만 진행·시간·에너지·안전한 exploration 비교
i* = arg maxi∈Cvalid Ji,   p* = pi*,0
유효 후보 중 우승한 미래 전체를 실행하지 않고, 첫 번째 짧은 waypoint 하나만 Nav2에 준다. 실행 뒤 다시 정지하고 관찰한다.
K × M × E × n ≤ Bcompute
상위 action 수 × action별 좌표 수 × ensemble 수 × 미래 step 수가 RTX 5080 deadline 예산 안이어야 한다. 중복 제거 → 거친 rollout → 상위 후보 정밀 rollout 순으로 줄인다.

9. Episodic Memory 위의 replay samplers

차이
Memory는 원본 운행 일지다. Sampler는 그 일지에서 이번 학습에 보여줄 장면을 골라주는 편집자다. Reference/Safe/Critical 원본을 세 replay buffer로 복제하지 않는다.

SAC persistent off-policy replay

DSAC = {(st, zt, pt, rt, st+1, dt)}
실제로 선택·실행한 EpisodeStep만 transition이 된다. Safe·Boundary·Critical·rare·recent·map-zone bucket에서 비율을 정해 뽑고, importance weight로 편향을 보정한다.

TGRPO current-policy trajectory group

G(s0) = {τ(1),…,τ(G)},   τ(g) ~ πcurrent
Memory에서 현실적인 같은 시작 상태를 고르고 현재 Candidate 정책이 여러 trajectory를 가상 생성한다. 같은 출발점끼리 상대 비교하며, 이 group buffer는 학습 step 뒤 버린다. 옛 정책 trajectory를 일반 replay처럼 섞지 않는다.

충돌·사람 침범·emergency stop은 가중 보상 이전에 terminal Critical이다. 미선택 rollout에는 실제 성공 label을 주지 않는다.

10. Stable–Candidate 업데이트

가중치를 저장하고 이어서 학습하는 일반 방식은 유지한다. 차이는 방금 업데이트한 가중치를 실제 로봇에 바로 쓰지 않는다는 것이다.

Stable v12 ── 복제·새 Episode 학습 ──> Candidate v13
                                          ├ unit/schema
                                          ├ offline holdout replay
                                          ├ simulation/6C-Lite
                                          ├ Pinky HIL
                                          └ 저위험 canary
                                      pass → Stable v13
                                      fail → 폐기, v12 유지

TGRPO checkpoint, SAC checkpoint, skill ontology, input/reward schema를 PolicyBundle로 묶는 것이 현재 안전 기본값이다. 승격한 뒤 이전 Stable은 rollback용으로 남는다. 학습은 정지/docked window에서만 한다.

11. Nav2와 Safety Supervisor 권한

Nav2 = 최종 경로 의사결정자채택 좌표와 넓은 Recovery Envelope를 받고 현재 costmap으로 실제 경로를 자유롭게 재계획한다.
Safety = 최종 움직임 의사결정자LiDAR zone, bumper, e-stop, 정지거리, 센서 freshness, lease/envelope를 보고 CLEAR/SLOW/STOP/EMERGENCY를 정한다.
Nav2 /cmd_vel_nav → Safety Supervisor → robot /cmd_vel
                         ├ CLEAR: 통과
                         ├ SLOW: 안전 scale 감속
                         ├ STOP: 0속도 + latch
                         └ EMERGENCY: 즉시 0, Fleet goal cancel 요청

YOLO/VLM은 semantic 보조일 뿐 유일한 비상정지 수단이 아니다. deterministic LiDAR protection zone과 bumper 경로는 GPU/VLM과 독립적으로 계속 동작한다. Nav2가 virtual path와 다른 길을 만들 수 있지만 Recovery Envelope 밖으로 나가면 Safety가 정지하고 Fleet Adapter가 cancel한다.

12. RTX 5080 성능·실패 정책

  1. Safety·센서 항상 우선
  2. YOLO 평상시 연속, 복구 중 저주기 유지
  3. VLM은 Trigger 시에만 3B/7B 4-bit load/infer
  4. 후보 progressive pruning 후 6C-Lite

15. 대안과 선행 연구

1안(기존 방안 B) · 채택

TGRPO Top-K → SAC 좌표 → 전 후보 6C-Lite → Nav2. 좌표 출력, 계층적 설명, 미래 위험 비교가 장점. 계산 예산·정책 호환·simulator bias 관리가 필요하다.

2안(기존 방안 A) · fallback

Spatial action → deterministic 좌표 mapper → Nav2. 데이터가 적어도 검증하기 쉽지만 임의 map 적응성이 낮다. SAC OOD가 불안정할 때 유용하다.

Reference/Safe/Critical 세 물리 buffer를 복제하지 않는다. Reference와 단일 Episodic Memory를 원본으로 두고 sampler view가 Safe/Boundary/Critical/rare/recent를 뽑는다. 그래야 같은 사건의 버전과 경계 사례가 갈라지지 않는다.

  • TGRPO — trajectory·step feedback을 고수준 recovery skill 연구에 제한 적용
  • ReMemNav — bounded episodic working memory의 참고
  • Retrieval-Augmented RL, RANa — 경험 검색과 정책 결합
  • EE-RL — explorer/expert와 replay 관점
  • PETS, TD-MPC2 — ensemble/world-model 기반 짧은 horizon planning
  • Nav2 MPPI, Collision Monitor — rollout controller와 독립 collision monitoring
Trihouse 조합의 차별점
검증 map graph + soft-outcome episodic memory + immutable incident + current-policy TGRPO groups + SAC 좌표 + 모든 후보 Lite rollout + winner 최신 재검사 + Nav2/Safety 이중 권한 경계를 실제 Pinky-Pro 단일 GPU 제약에 묶는다.
