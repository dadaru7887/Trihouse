# Trihouse 전용 영상 네트워크 설계

## 목표

Ubuntu 24.04 AI 서버가 ipTIME N604SR의 유선 LAN을 통해 로봇과 웹캠 PC의 영상을 받고, 동시에 강의실 공용 Wi-Fi를 통해 인터넷을 사용한다. 로봇과 웹캠 PC는 N604SR의 전용 Wi-Fi에 연결한다.

## 네트워크 구조

```text
강의실 공용 Wi-Fi (192.168.128.0/17)
             |
        wlo1 | 인터넷 기본 경로
       Ubuntu AI 서버
        eno1 | 192.168.0.9/24
             |
       N604SR LAN 포트
       192.168.0.1/24
             |
       Trihouse-Cam Wi-Fi
        |       |       |       |
     Pinky 1 Pinky 2 Webcam 1 Webcam 2
```

N604SR의 WAN 포트는 비워 두고 무선 멀티브리지는 사용하지 않는다. N604SR은 전용 LAN과 2.4GHz AP 역할만 담당한다. 서버만 두 네트워크에 동시에 연결되며, IP 포워딩이나 인터넷 공유 기능은 활성화하지 않는다.

## 주소 계획

| 장치 | 인터페이스 | 예약 IP |
|---|---|---:|
| N604SR | 내부 LAN | `192.168.0.1` |
| AI 서버 | `eno1` | `192.168.0.9` |
| Pinky-Pro 1 | N604SR Wi-Fi | `192.168.0.21` |
| Pinky-Pro 2 | N604SR Wi-Fi | `192.168.0.22` |
| 웹캠 PC 1 | N604SR Wi-Fi | `192.168.0.31` |
| 웹캠 PC 2 | N604SR Wi-Fi | `192.168.0.32` |

주소는 각 장치에 직접 입력하지 않고 N604SR의 DHCP 수동 주소 등록 기능으로 MAC 주소에 예약한다. Ubuntu 서버도 DHCP를 유지한다.

## N604SR 설정

### 1. 현재 상태 유지

- 내부 IP 주소: `192.168.0.1`
- DHCP 서버: 동작
- WAN 포트: 연결하지 않음
- 무선 멀티브리지: 사용하지 않음
- Easy Mesh: 사용하지 않음

`WAN포트 연결안됨` 표시는 이 설계에서는 정상이다.

### 2. 관리자 계정 보호

`시스템 관리 > 관리자 설정`에서 추측하기 어려운 관리자 암호를 설정한다. 무선 네트워크 암호와 관리자 암호는 서로 다르게 사용한다.

### 3. 전용 Wi-Fi 설정

`무선랜 관리 > 무선 설정/보안`에서 다음처럼 설정한다.

- 무선 동작: 사용
- 네트워크 이름(SSID): `Trihouse-Cam`
- SSID 숨김: 사용하지 않음
- 인증/암호화: `WPA2PSK + AES`
- 암호: 12자 이상의 별도 암호
- 채널 폭: 우선 `20 MHz`
- 채널: 주변 AP 검색 결과가 가장 적은 `1`, `6`, `11` 중 하나

영상 손실이 없고 더 많은 대역폭이 필요할 때만 채널 폭 40 MHz를 시험한다. 2.4GHz가 혼잡한 강의실에서는 20 MHz가 일반적으로 더 안정적이다.

게스트 네트워크, 무선 단말 격리, 내부 네트워크 단절 옵션은 사용하지 않는다. 해당 옵션이 켜지면 무선 장치가 유선 서버와 통신하지 못할 수 있다. WPS는 사용하지 않는다.

### 4. DHCP 주소 예약

장치를 하나씩 `Trihouse-Cam`에 연결한 뒤 `네트워크 관리 > 내부 네트워크 설정` 또는 DHCP 서버 화면의 사용 중인 IP 목록에서 MAC 주소를 확인한다. 위 주소 계획에 따라 각 장치를 수동 등록한다.

장치 이름이나 MAC 주소가 불분명하면 한 번에 하나만 연결하여 식별한다. 같은 IP를 두 MAC 주소에 등록하지 않는다.

## Ubuntu 서버 설정

### 1. 연결 프로필 확인

```bash
nmcli -t -f NAME,DEVICE connection show --active
```

출력에서 `eno1` 옆의 연결 프로필 이름을 확인한다. 다음 명령은 그 이름을 자동으로 읽어 변수에 저장한다.

### 2. 유선망을 인터넷 기본 경로에서 제외

```bash
WIRED_PROFILE_NAME="$(nmcli -g GENERAL.CONNECTION device show eno1)"
printf '%s\n' "$WIRED_PROFILE_NAME"
sudo nmcli connection modify "$WIRED_PROFILE_NAME" ipv4.method auto ipv4.never-default yes ipv6.never-default yes
sudo nmcli device reapply eno1
```

`reapply`가 지원되지 않으면 서버 앞에서 해당 유선 연결을 한 번 껐다 켠다. 브라우저의 공유기 관리 화면은 잠시 끊길 수 있다. Wi-Fi 연결 프로필은 수정하지 않는다.

### 3. 경로 검증

```bash
ip -br address
ip route
ip route get 1.1.1.1
ip route get 192.168.0.1
```

성공 기준은 다음과 같다.

- `eno1`에 `192.168.0.9/24`가 표시된다.
- `wlo1`에 강의실 Wi-Fi 주소가 표시된다.
- 인터넷 기본 경로가 `wlo1`을 사용한다.
- `192.168.0.0/24` 경로가 `eno1`을 사용한다.
- `eno1`을 통한 별도의 default 경로는 없다.

## 장치 연결과 검증

1. Pinky-Pro 1만 `Trihouse-Cam`에 연결하고 예약 IP `192.168.0.21`이 할당되는지 확인한다.
2. 서버에서 `ping -c 10 192.168.0.21`을 실행한다.
3. 같은 방식으로 `.22`, `.31`, `.32`를 차례로 연결하고 시험한다.
4. 네 장치를 모두 연결한 뒤 서버에서 각 주소로 동시에 통신되는지 확인한다.
5. 서버에서 `ping -c 3 1.1.1.1`과 `ping -c 3 google.com`을 실행해 인터넷과 DNS를 확인한다.

패킷 손실이 발생하면 먼저 각 장치의 신호 세기와 공유기 채널을 확인한다. 공유기는 바닥이나 금속 장비 뒤를 피하고 가능한 한 장치들이 보이는 높은 위치에 둔다.

## 초기 영상 전송 기준

- YOLO segmentation 입력: `1280x720`, `10-15 fps`
- 전송: H.264 스트림 또는 ROS 2 `image_transport`의 압축 전송
- 장치당 목표 비트레이트: 약 `1.5-3 Mbps`
- VLM 입력: 연속 원본 스트림을 별도로 보내지 않고 서버가 기존 스트림에서 필요한 프레임만 추출
- VLM 처리 빈도: 이벤트 기반 또는 최대 `1-2 fps`

비압축 RGB 영상은 사용하지 않는다. `1280x720`, 30fps 비압축 RGB 한 스트림만으로도 약 664Mbps가 필요해 N604SR 환경에서 전송할 수 없다.

## 실패 처리와 확장 기준

- 무선 단말끼리는 통신되지만 서버와 통신되지 않으면 단말 격리/내부 네트워크 단절 설정을 확인한다.
- 서버 인터넷이 끊기면 `ip route get 1.1.1.1`이 `wlo1`을 선택하는지 확인한다.
- 영상 지연이나 손실이 생기면 먼저 720p 10fps, 장치당 1.5Mbps로 낮춰 비교한다.
- 네 스트림 합계가 약 15-20Mbps인데도 불안정하면 N604SR을 기가비트 LAN과 5GHz Wi-Fi 6을 지원하는 AP로 교체한다.
- 로봇과 웹캠 PC에도 인터넷이 필요해지면 무선 멀티브리지를 켜지 말고 별도의 5GHz AP 또는 서버 NAT 설계를 추가 검토한다.

## 완료 조건

- 네 장치가 항상 예약된 `192.168.0.x` 주소를 받는다.
- 서버가 네 장치를 이름 또는 IP로 안정적으로 식별한다.
- 영상 트래픽은 `eno1`으로 들어오고 인터넷 트래픽은 `wlo1`으로 나간다.
- 네 개의 압축 영상 스트림을 동시에 실행해도 추론에 필요한 지연과 프레임률을 유지한다.
